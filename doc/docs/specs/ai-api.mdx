# AI API

The AI chat API enables pattern generation through a local Claude CLI integration. The endpoint receives user messages, spawns a Claude process, and writes pattern files to disk.

## Endpoint

```
POST /api/ai-chat
```

This route is server-side rendered (`export const prerender = false`) and requires the Node adapter.

## Request Format

```typescript
{
  message: string;          // Required. The user's request.
  history?: ChatMessage[];  // Optional. Previous conversation messages.
}

interface ChatMessage {
  role: "user" | "assistant";
  content: string;
}
```

### Validation Rules

| Field | Constraint |
|---|---|
| `message` | Required, non-empty string, max 4000 characters |
| `history` | Optional array, max 20 entries. Each entry must have valid `role` ("user" or "assistant") and `content` (string, max 4000 chars) |

## Response Format

### Pattern Creation (files_written)

When the AI creates new pattern files:

```json
{
  "action": "files_written",
  "files": ["breadcrumbs.astro"],
  "message": "Created 10 breadcrumb patterns! Click reload to see them.",
  "needsReload": true
}
```

### Chat Response

When the AI responds with text (no file creation):

```json
{
  "action": "chat",
  "message": "The token system uses CSS custom properties..."
}
```

### Error Responses

```json
// 400 Bad Request
{ "error": "message required" }
{ "error": "message too long" }
{ "error": "Invalid JSON" }

// 429 Too Many Requests
{ "error": "Another request is in progress. Please wait." }

// 500 Internal Server Error
{ "error": "Timeout after 60s" }
{ "error": "claude exited 1: <stderr output>" }
{ "error": "Spawn failed: <error message>" }
```

## System Prompt Overview

The AI receives a detailed system prompt that includes:

- Instructions to respond with structured JSON (not markdown)
- The exact Astro page template format
- The complete list of token variables with their values
- Rules for BEM-ish class naming
- The prohibition against arbitrary hex colors, pixel values, and HSL values
- Instructions for both pattern creation and general chat responses

The system prompt defines two response formats:

**Pattern creation** (`action: "create_patterns"`):

```json
{
  "action": "create_patterns",
  "category": "breadcrumbs",
  "label": "Breadcrumbs",
  "files": {
    "breadcrumbs.astro": "<full Astro page content>"
  },
  "sidebarEntry": {
    "slug": "breadcrumbs",
    "label": "Breadcrumbs",
    "count": 10
  },
  "message": "Created 10 breadcrumb patterns!"
}
```

**General chat** (`action: "chat"`):

```json
{
  "action": "chat",
  "message": "Your answer here"
}
```

## How AI Writes Files

### Process Flow

1. **Parse and validate** the incoming request JSON
2. **Read context**: Check which pattern pages exist on disk and read the current `sidebar-nav.tsx`
3. **Build prompt**: Combine the system prompt, conversation history, existing page context, and the user's message
4. **Spawn Claude CLI**:
   ```bash
   claude -p --model haiku --max-budget-usd 0.50 --system-prompt "..." < prompt
   ```
5. **Parse response**: Strip any markdown code fences, parse as JSON
6. **If `action: "create_patterns"`**:
   - Write each `.astro` file to `src/pages/`
   - Update `sidebar-nav.tsx` with the new category
   - Return `{ action: "files_written", ... }`
7. **If `action: "chat"` or plain text**:
   - Return `{ action: "chat", message: "..." }`

### File Safety

The endpoint enforces strict file writing rules:

- Only `.astro` files are written (other extensions are silently skipped)
- Path traversal is blocked (`..` and `/` in filenames are rejected)
- All files are written to the `src/pages/` directory only

## How sidebar-nav.tsx Is Auto-Updated

The `updateSidebarNav()` function modifies the sidebar categories:

```typescript
function updateSidebarNav(entry: {
  slug: string;
  label: string;
  count: number;
}) {
  // 1. Read sidebar-nav.tsx from disk
  // 2. Check if category slug already exists
  //    → If yes: update the count via regex
  //    → If no: insert a new entry before the closing "];"
  // 3. Write the modified file back to disk
}
```

The update uses regex-based string manipulation (not AST parsing) to modify the categories array in the source file.

**Example**: If the AI creates a "breadcrumbs" category with 10 patterns, this line is inserted:

```typescript
  { slug: "breadcrumbs", label: "Breadcrumbs", count: 10 },
```

## Rate Limiting

The endpoint uses a simple in-memory `inFlight` flag:

- Only **1 concurrent request** is allowed
- Additional requests receive HTTP 429 with `"Another request is in progress. Please wait."`
- The flag is cleared in a `finally` block to ensure cleanup even on errors

This is a module-level variable, so it works within a single Node.js process. It does not persist across server restarts.

## Input Validation

| Check | Behavior |
|---|---|
| Missing or non-string `message` | 400: "message required" |
| `message` > 4000 chars | 400: "message too long" |
| Invalid JSON body | 400: "Invalid JSON" |
| `history` items with invalid `role` | Silently filtered out |
| `history` items with `content` > 4000 chars | Silently filtered out |
| `history` > 20 items | Truncated to last 20 |
| Concurrent request | 429: "Another request is in progress" |

## Local Claude CLI Integration

The API spawns the `claude` CLI as a child process:

```typescript
const proc = spawn("claude", [
  "-p",
  "--model", "haiku",
  "--max-budget-usd", "0.50",
  "--system-prompt", SYSTEM_PROMPT,
], { stdio: ["pipe", "pipe", "pipe"] });
```

### Configuration

| Parameter | Value |
|---|---|
| Mode | `-p` (pipe/non-interactive) |
| Model | `haiku` |
| Budget limit | $0.50 per request |
| Timeout | 60 seconds |

### Error Handling

- **Timeout**: After 60s, the process is killed with `proc.kill()` and a "Timeout after 60s" error is returned
- **Non-zero exit code**: Returns the stderr output in the error message
- **Spawn failure**: Returns "Spawn failed" with the OS error
- **Invalid JSON response**: Falls back to returning the raw text as a chat message
