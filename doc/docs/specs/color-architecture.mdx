# Color Architecture

CSS Playground uses a three-tier color cascade with CSS custom properties. Colors flow from raw palette values through semantic assignments to component-level overrides — all controlled by the `--cssp-*` variable namespace.

## Three-Tier Color Cascade

### Tier 1 — Palette

The raw palette is a set of 16 indexed colors (`--cssp-0` through `--cssp-15`). These are the foundational color values that all other tokens derive from.

The ColorTweakPanel edits these directly, and presets swap the entire palette at once.

### Tier 2 — Semantic

Semantic tokens (`--cssp-bg`, `--cssp-accent`, etc.) map purpose to color. Components reference semantic tokens so that switching palettes updates the entire UI consistently.

```css
/* Defined in :root of tokens.css */
:root {
  --cssp-bg: #1e1e2e;
  --cssp-fg: #cdd6f4;
  --cssp-surface: #313244;
  --cssp-muted: #6c7086;
  --cssp-accent: #89b4fa;
  --cssp-accent-hover: #b4d0fb;
  --cssp-success: #a6e3a1;
  --cssp-danger: #f38ba8;
  --cssp-warning: #f9e2af;
  --cssp-info: #89dceb;
}
```

### Tier 3 — Component

Component-specific overrides via scoped CSS. No predefined variables — components simply reassign Tier 2 variables locally when needed.

```css
/* Example: a card that uses info as its accent */
.info-card {
  --cssp-accent: var(--cssp-info);
}
```

## CSS Variable Naming Convention

All color variables use the `--cssp-*` prefix (CSS Playground):

- `--cssp-{0-15}` — Palette indices
- `--cssp-bg` — Background
- `--cssp-fg` — Foreground
- `--cssp-surface` — Elevated surface
- `--cssp-muted` — Muted/secondary text
- `--cssp-accent` — Primary interactive
- `--cssp-accent-hover` — Accent hover state
- `--cssp-success` — Success state
- `--cssp-danger` — Danger/error state
- `--cssp-warning` — Warning state
- `--cssp-info` — Informational state

The `@theme` block in `tokens.css` bridges these to Tailwind's `--color-*` namespace:

```css
@theme {
  --color-bg: var(--cssp-bg);
  --color-fg: var(--cssp-fg);
  --color-surface: var(--cssp-surface);
  /* ... */
  --color-p0: var(--cssp-0);
  --color-p1: var(--cssp-1);
  /* ... */
}
```

## How ColorTweakPanel Updates Colors

The panel has three sections that mirror the three-tier color cascade:

1. **PALETTE** — An 8x2 grid of large clickable swatches (p0-p15). Clicking a swatch opens an HSL picker popover with hue, saturation, and lightness sliders plus a hex input.
2. **BASE** — PaletteSelector dropdowns for `bg` and `fg`, mapping each to a palette index.
3. **SEMANTIC TOKENS** — PaletteSelector dropdowns for all semantic tokens (surface, muted, accent, etc.), each mapping to a palette index.

### State Model

The panel uses palette-index-based mapping for semantic tokens:

```typescript
interface TweakState {
  palette: string[]; // 16 hex colors
  semanticMappings: Record<string, number>; // semantic key -> palette index
}
```

Each semantic token points to a palette index rather than storing an independent color value. This enforces the constraint that semantic colors always derive from the palette.

### Applying Changes

The panel calls `applyToDocument()` on every change:

```typescript
function applyToDocument(state: TweakState) {
  const el = document.documentElement;
  // Set palette variables
  state.palette.forEach((color, i) => {
    el.style.setProperty(`--cssp-${i}`, color);
  });
  // Resolve semantic variables from palette indices
  SEMANTIC_FIELDS.forEach(({ key, cssVar }) => {
    const paletteIndex = state.semanticMappings[key];
    el.style.setProperty(cssVar, state.palette[paletteIndex]);
  });
}
```

This sets properties directly on `document.documentElement.style`, which overrides the values from `tokens.css`. The change is instant and affects every element on the page that references `--cssp-*` variables.

State is persisted to localStorage under the key `cssp-tweak-state`.

## How to Create a New Preset

To add a new color preset:

1. Open `src/components/color-tweak-panel.tsx`
2. Add a new entry to the `PRESETS` object:

```typescript
const PRESETS: Record<string, PresetDef> = {
  // ... existing presets ...
  "My Theme": {
    palette: [
      "#000000",
      "#ff0000",
      "#00ff00",
      "#ffff00",
      "#0000ff",
      "#ff00ff",
      "#00ffff",
      "#ffffff",
      "#808080",
      "#ff0000",
      "#00ff00",
      "#ffff00",
      "#0000ff",
      "#ff00ff",
      "#00ffff",
      "#c0c0c0",
    ],
    semanticMappings: {
      bg: 0, // p0
      fg: 7, // p7
      surface: 0, // p0
      muted: 8, // p8
      accent: 4, // p4
      accentHover: 6, // p6
      success: 2, // p2
      danger: 1, // p1
      warning: 3, // p3
      info: 6, // p6
    },
  },
};
```

3. The preset will automatically appear in the ColorTweakPanel's dropdown selector

Requirements for a preset:

- `palette`: Array of exactly 16 hex color strings
- `semanticMappings`: Object mapping each semantic key to a palette index (0-15)
- All 10 semantic keys must be set: `bg`, `fg`, `surface`, `muted`, `accent`, `accentHover`, `success`, `danger`, `warning`, `info`
