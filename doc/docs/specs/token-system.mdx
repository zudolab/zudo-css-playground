# Token System

The token system is the foundation of CSS Playground. Every spacing value, color, font size, border radius, and shadow in the entire application — whether hand-authored or AI-generated — must come from a design token. No arbitrary values are allowed.

## Why Tokens

Tokens solve two problems:

1. **Consistency**: Every pattern looks like it belongs to the same design system, regardless of who (or what) created it
2. **AI reliability**: The AI is given a fixed set of token variables and strict instructions to use only those variables. This prevents the AI from inventing random hex colors or magic pixel numbers

The token definitions live in `src/styles/tokens.css` and are exposed to both Tailwind (for component styling) and the HtmlPreview iframe (for pattern demos).

### Tier 2 — Semantic (Purpose-Based)

Semantic tokens give meaning to palette colors. Components and layouts reference these instead of raw palette indices.

| Variable | Default | Purpose |
|---|---|---|
| `--cssp-bg` | `#1e1e2e` | Page background |
| `--cssp-fg` | `#cdd6f4` | Primary text |
| `--cssp-surface` | `#313244` | Elevated surfaces (cards, panels, sidebar) |
| `--cssp-muted` | `#6c7086` | Secondary/disabled text |
| `--cssp-accent` | `#89b4fa` | Primary actions, links, interactive elements |
| `--cssp-accent-hover` | `#b4d0fb` | Accent hover state |
| `--cssp-success` | `#a6e3a1` | Success messages and indicators |
| `--cssp-danger` | `#f38ba8` | Errors, destructive actions |
| `--cssp-warning` | `#f9e2af` | Warnings, caution states |
| `--cssp-info` | `#89dceb` | Informational messages |

### Tier 3 — Component (CSS Overrides)

Component-specific color overrides are applied via CSS. For example, a specific card variant might remap `--cssp-accent` locally. This tier is implicit — there are no predefined component tokens. Instead, components use Tier 2 variables and override them with scoped CSS when needed.

### Tailwind Color Classes

The `@theme` block in `tokens.css` bridges CSS variables to Tailwind utilities:

```css
@theme {
  --color-bg: var(--cssp-bg);
  --color-accent: var(--cssp-accent);
  /* etc. */
}
```

This enables classes like `bg-bg`, `text-accent`, `border-muted`, `text-danger`, etc.

## Rules for AI and Humans

These rules apply to all pattern CSS — whether written by hand or generated by the AI:

1. **NEVER use arbitrary hex colors** — use `var(--accent)`, `var(--fg)`, `var(--bg)`, etc.
2. **NEVER use arbitrary pixel values for spacing** — use `var(--space-xs)`, `var(--space-sm)`, `var(--space-md)`, `var(--space-lg)`
3. **NEVER use arbitrary font sizes** — use `var(--font-sm)`, `var(--font-md)`, `var(--font-lg)`
4. **NEVER use arbitrary border radius** — use `var(--radius)`
5. **NEVER use arbitrary shadows** — use `var(--shadow)` or `var(--shadow-strong)`
6. **Use BEM-ish class names** — e.g., `.card-1`, `.card-1__title`, `.card-1__title--active`
7. **CSS-only interactions** — no JavaScript inside pattern demos. Use `:hover`, `:focus-visible`, and CSS transitions
8. **Font family is inherited** — the iframe sets `font-family: system-ui, sans-serif` on `body`. Don't redeclare it in patterns
9. **Focus styles are inherited** — the iframe sets `:focus-visible` outline. Don't override it unless intentional

The AI's system prompt includes these exact rules and the full token reference. Violations will produce inconsistent patterns that look out of place.
